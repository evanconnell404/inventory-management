Factory Inventory Management System

Architecture overview. A Vue 3 single-page app talks over REST to a FastAPI service that serves in-memory data loaded from JSON files. There is no database.

System architecture

Three runtime pieces: browser app, API service, and a JSON data layer loaded at startup.

Data flow

How a filter change on the Dashboard becomes updated numbers on screen.

  1. Filter change. The user picks a period, warehouse, category, or order status in FilterBar. The values live in refs inside the shared useFilters composable, so every view sees the same state.
  2. Request. The view calls getCurrentFilters() and passes the result to a method in api.js. Values equal to all are dropped, and the rest become query params (warehouse, category, status, month).
  3. Routing. FastAPI matches the path, for example GET /api/dashboard/summary, and CORS lets the browser accept the cross-origin response from port 8001.
  4. Filtering. The handler runs apply_filters and filter_by_month over the lists that mock_data.py loaded at startup. Nothing is read from disk per request.
  5. Validation. List endpoints return through Pydantic response_models, which enforce the JSON shape. The dashboard summary is aggregated in the handler and returned as a plain dict.
  6. Render. The view stores the raw response in refs (for example allOrders, inventoryItems). Derived values such as totals and chart series are computed properties, so the UI updates reactively.

Things to know

Frontend and backend are out of sync. api.js calls /api/tasks (list, create, toggle, delete) and /api/purchase-orders (create, get by backlog item), but main.py defines no routes for them. Those calls will return 404 until the endpoints are added.
  • All data is read-only sample data from September 2025. Restarting the backend resets nothing because nothing is written.
  • Inventory has no time dimension, so it ignores the month filter.
  • The API base URL is hard-coded to http://localhost:8001/api in api.js.
  • CORS allows every origin, which is acceptable for a local demo only.
  • The user profile and task list in useAuth.js are mock data on the client.
